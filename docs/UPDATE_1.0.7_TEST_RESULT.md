
**结论：在线首播慢在 `resolve`（1.5–2.2s，其中含一次失败的 tx 请求 + 跨平台搜索 + 重新取址），不在 `buffer`（0.6s）；缓存命中时 resolve=0、buffer=39ms，端到端 40ms。**
下一步优化方向（1.0.8）：
1. **修 tx 源** —— 每首 QQ 源歌都要先失败一次再换源，这次失败本身就占 resolve 的大头；
2. **下一首直链预解析**（现只预取已缓存文件），把 resolve 挪到上一首的播放间隙；
3. 直链缓存 TTL 复核（`MediaCache.getMusicUrl` 命中率）。

## 四、测试后追加的代码改动（已编译、已复验）

`core/player/PlaySession.ets`：已下载文件 / 沙箱缓存两条分支在 `playLocal` 前补 `StartupTiming.beginBuffer(..., true)`。

原因：这两条分支原本直接 `return`，不结算 buffer 段，导致「复播」永远不出耗时日志，排障时会把缓存命中误读成「没触发」。
复验：`resolve=0ms buffer=39ms 命中缓存=true` —— 通过。
