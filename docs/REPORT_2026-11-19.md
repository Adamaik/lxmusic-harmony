## 二、桌面歌词：为什么「位置每次开关会重置」改不了（已逐项核实）

桌面歌词不是本应用自绘的窗口，而是**系统的歌词悬浮窗**。核实过程与证据：

**证据 1：全部 SDK 声明里，桌面歌词只有开关类接口，没有任何位置/样式字段。**
对 `sdk/default/openharmony/ets/api/` 下所有 `*.d.ts` 做全文检索，含桌面歌词接口的文件只有
`@ohos.multimedia.avsession.d.ts`（31 处），且方法仅有：

```
isDesktopLyricSupported()
enableDesktopLyric(enable)
setDesktopLyricVisible(visible)
isDesktopLyricVisible()
on/offDesktopLyricVisibilityChanged()
setDesktopLyricState(state) / getDesktopLyricState() / on/offDesktopLyricStateChanged()
// controller 侧：isDesktopLyricEnabled() / on/offDesktopLyricEnabled()

interface DesktopLyricState { isLocked: boolean; }   // ← 全文只有这一个字段
```

没有 `position / x / y / offset / style / fontSize / color / stroke` 任何一项。
所以「上次拖到哪」应用**读不到**，也无法在重新显示时恢复；「描边」也一样，
文字是系统渲染的，应用只能提供 LRC 文本。

**证据 2：自绘一个「浮在其它应用之上」的歌词窗，普通应用没有权限。**
`@ohos.window.d.ts` 里唯一的全局悬浮窗类型是

```
TYPE_FLOAT = 8,   // Global floating window
* @permission ohos.permission.SYSTEM_FLOAT_WINDOW [since 12]
```

该权限属系统级（system_basic），只有系统应用签名才授予；本工程是普通应用（debug 签名、
`module.json5` 只申请 INTERNET / KEEP_BACKGROUND_RUNNING / MICROPHONE 等），拿不到。
另一条近似路线 PiP（画中画）只能承载视频画面、且位置同样由系统管理，做歌词也不合适。

**证据 3：仓库里没有自绘实现可改。**
`git log -S 'DesktopLyric'` 只有 3 个提交，且 `PlaybackService.ets` 的桌面歌词一节
（`setupDesktopLyric / refreshDesktopLyric / syncDesktopLyric`）调用的全是上面那套系统接口；
全仓库没有 `createSubWindow / TYPE_FLOAT / SYSTEM_FLOAT_WINDOW` 的任何用法。

**现有实现已经做了能做到的最小化：**
- 组件在会话创建时只 `enableDesktopLyric(true)` 一次；
- 平时只用 `setDesktopLyricVisible()` 显隐，暂停不收起（避免一显一隐地闪）；
- 只有「停播 / 换到没有词的歌 / 用户关掉开关」才隐藏。

但 `visible=false` 之后窗口由系统回收，再显示按系统默认位置摆放 —— 这是系统行为，应用无从干预。

**结论：确认不能做。** 位置记忆与文字描边都受系统接口所限。
要突破只有两条路，都不现实：① 申请 `SYSTEM_FLOAT_WINDOW` 做系统应用；② 自绘悬浮窗
（需要该权限 + 自己做滚动渲染与手势 + 自己做权限引导）。
如果只是「每次开关都回到默认位置」很烦，可以试一个折中：**保持本应用里的桌面歌词开关常开**，
改用系统音频控制中心去显隐（用户已经找到入口）——这样不经过我们的隐藏逻辑，位置或许更稳。
这条是推测，需要真机验证后才能下结论。
