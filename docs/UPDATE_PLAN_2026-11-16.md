## 二、待办项（按优先级）

### P0-1 在线播放起播慢（新问题，最影响体验）

- **反馈**：11-15 皮永祥「下载很快，但是在线听要很久才播放」。
- **现象拆解**：下载链路正常 ⇒ 网络不背锅；慢在「取直链 → AVPlayer prepare → 出声」这一段。
- **需要先做的诊断**（不加埋点无法定位，不要盲改）：
  1. 在取直链处（音源脚本 `musicUrl` 调用返回点）与 `AVPlayer` 进入 `prepared` 处各打一条带毫秒差的日志，拆成 `resolveMs` / `bufferMs`。
  2. 对比「同网络下华为音乐/洛雪」是否同样慢，锁定是源侧还是播放器侧。
- **候选修复方向**：
  - 若 `resolveMs` 大：音源脚本每次都重新请求 → 加直链短期缓存（同曲目 10 分钟内复用），并发预解析**下一首**。
  - 若 `bufferMs` 大：检查 `playbackStrategy()`（LxPlayer.ets:434 附近）的预缓冲参数与 `preferredBufferDuration`，必要时对慢源降码率/换 CDN 域名。
- **落点**：`core/player/LxPlayer.ets`、`core/player/PlaySession.ets`、`core/source/SourceEngine.ets`（取直链处）。
- **验收**：从点击到出声的首帧耗时日志可见，且在弱网下不再出现「转圈 10 秒以上」。

### P0-2 QQ 音乐音源放不了（影响面最大，用户换遍源都不行）

- **反馈**：11-12 小冰「换了好多源，都是只有 qq 音乐放不了」；StarFlame「aya 还能用，独家 v7 貌似寄了」。
- **判断**：多套第三方源同时只在 `tx` 平台失败 ⇒ 不是单个脚本问题，是 **QQ 音乐侧接口/鉴权/端口策略变化**。
- **修复方向**：
  1. 先确认是「直链 403」还是「接口签名失败」——现有 `core/music/LxCrypto.ets` 已实现 `tx` 的 zzcSign，可直接对照验证。
  2. 若签名失效：更新签名算法与请求头（UA / Referer / Cookie 域）。
  3. 若被限流/封端口：加 **平台级失败降级**——`tx` 解析失败时自动回退 `wy/kw/kg` 同名歌曲，并在 UI 上提示「已换源播放」而不是直接报错。
  4. 内置源与用户导入源分离：内置源随版本更新，避免用户自己找源。
- **落点**：`core/music/LxCrypto.ets`、`core/source/SourceEngine.ets`、`core/source/LxTypes.ets`（平台回退）。
- **验收**：`tx` 平台在真机上可播放热门榜单歌曲；失败时 3 秒内自动换源成功而非报错。

### P1-3 自建歌单缺搜索框（已口头承诺）

- **反馈**：11-10 StarFlame，开发者已答「收到，不难」。
- **现状**：`views/PlaylistDetailView.ets` 内全文无 Search 相关实现（已核对）。
- **做法**：
  - 列表顶部加折叠式搜索框（滚动时收起），按**歌名 + 歌手**实时过滤，支持拼音首字母可选。
  - 空结果态给「没有匹配的歌」+ 一键清除；搜索态下隐藏「播放全部」以免歧义。
  - 复用聚合搜索已有的匹配/高亮组件，别新写一套。
- **落点**：`views/PlaylistDetailView.ets`（+ 若需，`ui/Widgets.ets` 抽公共搜索框）。
- **验收**：1000 首歌单输入即时过滤无卡顿（列表用 LazyForEach 已有分页能力时优先复用）。

### P1-4 日志看不到「全文」（已承诺加展示功能）

- **反馈**：11-12 小冰（连问两次），开发者「我回去加个展示日志的功能」。
- **根因（已定位）**：`core/source/SourceEngine.ets:884` 把日志文本裁到 200 字符再入面板：
  ```ts
  const clipped: string = text.length > 200 ? `${text.substring(0, 200)}…` : text;
  ```
  面板（`views/SourceSettingsView.ets`「引擎日志」）只渲染裁剪后的行，所以用户永远看不到完整返回体。
- **做法**：
  1. **存储与展示分离**：日志对象保留 `full` 原文，面板仍显示裁剪版；点击某行 → 弹「日志详情」页展示全文，带「复制」按钮。
  2. 详情页支持上下条切换与按级别过滤（error 优先）。
  3. 「引擎日志」卡片右上角加「复制全部 / 导出到文件」，方便用户回贴给我们排查。
- **落点**：`core/source/SourceEngine.ets`（日志结构）、`core/source/LxTypes.ets`、`views/SourceSettingsView.ets`、新增 `views/LogDetailView.ets`。
- **验收**：任意一条含长响应的日志，都能在应用内完整查看并复制全文。

### P1-5 在线榜单「批量收进歌单」（多选已具备，需补确认与公告）

- **反馈**：11-12 自取其乐「热歌榜能一键导入歌单吗」→ 开发者「那我加上」。
- **现状（已核对代码）**：`views/OnlineListView.ets` 已有长按多选 + 行上爱心收藏 + 「添加到歌单」批量动作（`MULTI_ACTIONS`，红字主操作「收藏」）。**大概率已随第六版发布，用户没发现入口。**
- **做法**：
  1. 真机回归确认入口可达性（长按才进多选，用户不知道 → 属于可发现性问题）。
  2. 首次进入在线列表时给一次「长按可多选」轻提示（仅一次，可永久关闭）。
  3. 更新公告里明确写「榜单支持长按多选，可批量收藏 / 加入歌单」。
- **落点**：`views/OnlineListView.ets`、`core/changelog/Changelog.ets`。
- **验收**：新用户在不看文档的情况下 30 秒内能完成「全选 → 加入歌单」。

### P2-6 安装分发与车机说明（降噪项，减少重复问答）

- **反馈**：11-09 NULL「编译/注册太麻烦放弃了」、跟着大王好好混「卡在 apptest 安装页 / 得不到包」；HiCar 询问 2 次。

  3. 「如何自己编译」——DevEco 一键编译 + 自签名 vs 分发签名的差异。
- **落点**：`views/AboutView.ets` / 帮助页 + 群公告置顶同步。
- **验收**：同类问题在群里重复提问次数下降。
