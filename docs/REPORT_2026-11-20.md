## 二、⑧ 的两件事：先看清图，再动手

这两条反馈看起来是一件事（「没封面」），实际是**两个不同的问题**，只有把图打开看才能分清：

1. **14:47 那张**：推荐页「歌单分类」（推荐 / 最热 / 最新）三张卡，卡面只有首字水印，
   红圈圈住的正是这三张 → 分类卡**从来没有封面**。分类本身是平台的排序档位，接口不给封面。
   处理：用**该分类下第一张歌单的封面**（广场第一页里现成就有 `img`，不额外取歌单详情），
   逐档顺序取、每档只取第一页；取不到就继续走玻璃卡。封面是**后到**的，所以拼进了 ForEach 的 key，
   否则卡面会永远停在玻璃卡上（V1 下 key 没变的条目不会重跑生成器）。

2. **15:28 那张长截图**：其实是**歌单详情里的歌曲列表**，整列都是首字占位，只有底部少数几首有图
   → 不是广场卡片的问题。查下来是酷狗两条歌曲映射都写死 `img: ''`，**从来没读过封面字段**：
   - 歌单详情走 gateway `/v2/album_audio/audio` → `album_info.sizable_cover`
   - 榜单走 `mobilecdn/api/v3/rank/song` → `album_sizable_cover`
   两者都是 `http://imge.kugou.com/stdmusic/{size}/...` 模板，替换成 400 档（实测 http/https 都通，
   统一升 https），`trans_param.union_cover` 兜底。

另外顺带核实过：四个平台的歌单广场封面 URL **全是 http**（只有咪咕是 https），所以这不是
「明文 HTTP 被系统拦」的问题——桌面端逐条拉取 20/20 都是 `200 image/jpeg`。

## 三、⑩「不感兴趣」：只做用户说的那件事

反馈原话是「推荐歌曲功能老是推荐各种抖音短视频歌曲，全是各种变速和烟嗓版，有没有不感兴趣按钮」，
指的是**首页「推荐歌曲」那排大卡**，不是探索页（探索页本来就是「下滑=不喜欢」）。

实现边界刻意收窄：
- **只做「用户明确说了不要的，别再摆到他面前」**，不碰推荐权重。画像 / 负反馈是另一条线
  （`core/heart`，见 `docs/RECOMMEND_HANDOFF.md`，由另一路在处理）。
- key 用「歌名+歌手」归一化，不用歌曲 id：同一首歌各平台 id 不同，用户说「别再推这首」是内容层面的意思。
- 不做「去括号 / 去 Live 后缀」的模糊匹配：那会把《某歌》和《某歌 (Live)》当成同一首，误伤比漏杀更难受。
- 落盘（沙箱 `dismissed_songs.json`，上限 500 条 FIFO）——只在内存里记着等于没做。
- 给后悔的出口：设置页「清空不感兴趣名单」+ 二次确认。

## 四、⑨ 摘下耳机暂停：系统不会替应用做

系统在耳机断开时**不会**暂停播放，只是把声音改从外放出来（这正是尴尬的来源）。所以要自己听
`AudioRoutingManager` 的设备变化：

- 事件是三参形态 `on('deviceChange', DeviceFlag, cb)`，枚举成员名是 **`ALL_DEVICES_FLAG`**
  （不是 `ALL_DEVICES`，SDK 里只有 `OUTPUT_DEVICES_FLAG` / `INPUT_DEVICES_FLAG` / `ALL_DEVICES_FLAG`）。
- 只认「断开的设备里有耳机类」（有线 / 蓝牙 SCO / 蓝牙 A2DP / USB）；外放设备断开不算。
- 只有在播放中、且设置开着时才暂停；挂载失败（老系统没有 `getRoutingManager`）只记日志，不影响播放。
- 开关默认**开**（绝大多数音乐 App 的行为），落盘持久化。

## 六、两件「系统能力所限」的确认（已逐项核实，不是没做）

### 6.1 桌面歌词位置每次开关就重置

桌面歌词不是本应用自绘的窗口，而是**系统的歌词悬浮窗**。对 `sdk/.../ets/api/` 下所有 `*.d.ts`
全文检索，含桌面歌词接口的文件只有 `@ohos.multimedia.avsession.d.ts`（31 处），方法仅有：

```
isDesktopLyricSupported() / enableDesktopLyric(enable) / setDesktopLyricVisible(visible)
isDesktopLyricVisible() / on/offDesktopLyricVisibilityChanged()
setDesktopLyricState(state) / getDesktopLyricState() / on/offDesktopLyricStateChanged()
接口的字段只有 DesktopLyricState { isLocked: boolean }
```

没有 `position / x / y / offset / style / fontSize / color / stroke` 任何一项 → 上次拖到哪应用**读不到**，
重新显示时无法恢复；描边同理（文字由系统渲染，应用只能提供 LRC 文本）。

自绘一个「浮在其它应用之上」的歌词窗也不行：`@ohos.window.d.ts` 里唯一的全局悬浮窗
`WindowType.TYPE_FLOAT = 8` 要求 `ohos.permission.SYSTEM_FLOAT_WINDOW`（system_basic，三方应用申请不到）。

### 6.2 桌面歌词「开关后不即时生效」

这是**能修**的（不属于系统限制），根因是我方推送顺序：先 `setDesktopLyricVisible(true)` 再推歌词，
系统在没收到元数据那一瞬就显示成空。已改成「先重推当前元数据、再 show」，真机实测 0.66 s 内出现
（`c7a30f3`）。同一批还修了歌词开头 BOM 导致「无歌词，请欣赏」（`262c787`）。
